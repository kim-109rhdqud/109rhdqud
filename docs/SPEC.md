## 원본 프롬프트 전문

현대의 밈, 유행어, 유행 상품과 인터넷 트렌드를 검색하고 그 맥락까지 한눈에 이해할 수 있는 웹서비스를 개발해줘.

서비스의 핵심 콘셉트는 **"이건 무슨 밈이지?", "이건 왜 유행하는 거지?", "요즘 사람들이 왜 이 말을 쓰지?"라는 궁금증을 바로 해결해주는 밈·트렌드 사전**이야.

단순 검색 결과를 보여주는 사이트가 아니라, 하나의 밈이나 유행을 검색했을 때 **뜻, 유래, 유행 시기, 관련 영상, 관련 밈, 관련 인물, 확산 맥락**까지 한 화면에서 이해할 수 있도록 구성해줘.

## 1. 서비스의 핵심 기능

### A. 메인 페이지

웹사이트에 접속하면 가장 먼저 커다란 검색창이 보이도록 구성해줘.

페이지의 중심에는 다음과 같은 느낌의 문구를 배치해줘.

**"이게 무슨 밈이지?"** **"요즘 이건 왜 유행해?"**

그 아래에 크고 직관적인 검색창을 배치해줘.

검색창 placeholder 예시는 다음과 같아.

- "밈, 유행어, 상품을 검색해봐"
- "예: 두쫀쿠, 야르, 킹받네"
- "무슨 뜻인지 궁금한 걸 검색해봐"

검색창에는 자동완성 또는 검색 추천 기능을 넣어줘.

사용자가 검색하면 해당 밈/유행의 상세 페이지로 이동하도록 해줘.

---

### B. 트렌드 랭킹

메인 검색창 아래에는 현재 사람들이 많이 찾거나 화제가 되고 있는 밈과 유행을 랭킹 형태로 보여줘.

기간별로 구분할 수 있도록 다음 탭을 만들어줘.

**일간 / 주간 / 연간**

예시:

일간

1. 두쫀쿠
2. 야르
3. ○○ 챌린지
4. ○○ 밈
5. ○○ 상품

주간

1. ...
2. ...
3. ...

연간

1. ...
2. ...
3. ...

각 트렌드에는 랭킹 순위와 함께 간단한 지표를 표시해줘.

가능한 지표:

- 조회수
- 검색량
- 언급량
- 사용 빈도
- 화제성
- 전주 대비 상승/하락
- 신규 진입 여부

예를 들어 다음과 같은 형태로 보여줘.

**1위 두쫀쿠** 검색량 128K · 언급량 +32% ▲ 3

단, 실제 데이터가 없는 초기 개발 단계에서는 가상의 mock data를 사용하고, 실제 서비스로 확장할 경우 API나 데이터 수집 시스템을 연결할 수 있도록 구조를 설계해줘.

---

## 2. 검색 결과 페이지

사용자가 검색하면 검색 결과 페이지가 나타나도록 해줘.

검색어에 대해 다음 카테고리로 결과를 분류해줘.

- 밈
- 유행어
- 상품
- 인물
- 챌린지
- 영상
- 기타

검색 결과 카드에는 다음 정보를 간략하게 보여줘.

**이름** 짧은 설명 카테고리 유행 시기 현재 화제성 관련 키워드

검색 결과가 충분히 명확하면 가장 관련성이 높은 항목을 상단에 크게 보여줘.

---

## 3. 밈 상세 페이지

각 밈이나 유행마다 독립적인 상세 페이지를 만들어줘.

이 사이트의 핵심 페이지이므로 가장 정보 구조가 잘 보이도록 설계해줘.

페이지 상단에는 다음을 배치해줘.

### 밈 이름

예: **두쫀쿠**

### 한 줄 설명

"최근 SNS와 커뮤니티를 중심으로 화제가 된 디저트 관련 유행어/상품"

### 핵심 정보

카드 형태로 다음 정보를 보여줘.

- 무엇인지
- 유행 시기
- 주요 플랫폼
- 현재 화제성
- 카테고리
- 관련 키워드

---

## 4. 밈 설명 영역

상세 페이지에서 사용자가 해당 밈을 바로 이해할 수 있도록 설명해줘.

구조는 다음과 같이 구성해줘.

### 이게 뭐야?

밈이나 유행을 처음 접한 사람도 이해할 수 있도록 아주 쉽게 설명.

### 왜 유행했어?

유행하게 된 계기와 확산 과정을 설명.

### 어떻게 사용하는 거야?

실제 인터넷에서 어떤 상황에서 사용되는지 설명.

### 한 줄 요약

처음 보는 사람이 10초 안에 이해할 수 있는 요약.

설명은 긴 글 하나로 작성하지 말고 짧은 문단과 카드, 태그 등을 이용해 가독성을 높여줘.

---

## 5. 유래와 확산 과정

밈이나 유행의 유래를 타임라인 형태로 표현해줘.

예:

2025.01 처음 등장
↓
2025.02 SNS에서 확산
↓
2025.03 유명 인물이 사용
↓
2025.04 대중적으로 유행

정확한 데이터가 없는 경우에는 임의로 사실처럼 작성하지 말고 mock data임을 명확히 표시할 수 있도록 해줘.

---

## 6. 관련 영상

상세 페이지에 관련 영상을 보여주는 영역을 만들어줘.

영상 썸네일과 제목을 카드 형태로 보여줘.

예:

[영상 썸네일] "두쫀쿠가 대체 뭐길래?"

YouTube 등의 실제 영상 플랫폼 API를 연결할 수 있도록 확장 가능한 구조로 만들어줘.

초기 버전에서는 mock video data를 사용해도 돼.

---

## 7. 관련 밈

현재 보고 있는 밈과 관련성이 높은 다른 밈들을 보여줘.

예:

**두쫀쿠** → 관련 밈 → 관련 유행어 → 관련 상품 → 관련 챌린지

각 항목은 클릭하면 해당 상세 페이지로 이동하도록 만들어줘.

---

## 8. 관련 인물

해당 밈이나 유행을 확산시키는 데 중요한 역할을 한 인물이나 계정이 있다면 보여줘.

카드에는 다음 정보를 포함해줘.

- 인물명
- 프로필 이미지
- 관련 이유
- 관련 콘텐츠

단, 실제 사실관계를 확인하지 않은 정보를 임의로 생성하지 않도록 데이터 출처를 표시할 수 있는 구조를 만들어줘.

---

## 9. 유행 지표

상세 페이지에 해당 밈의 인기도와 화제성을 시각적으로 보여주는 영역을 만들어줘.

예:

**화제성** ████████░░ 82
**검색량** █████████░ 91
**사용 빈도** ███████░░░ 74

또는 간단한 line chart를 사용해 시간에 따른 관심도 변화를 보여줘.

데이터가 존재하지 않는 초기 버전에서는 mock data임을 명시해줘.

---

## 10. 스크랩 기능

회원가입 및 로그인을 지원해줘.

사용자는 마음에 드는 밈 페이지를 **스크랩 / 저장**할 수 있어야 해.

상세 페이지에 다음 버튼을 넣어줘.

**♡ 스크랩**

스크랩한 콘텐츠는 개인 페이지에서 확인할 수 있도록 해줘.

### 마이페이지

다음과 같이 구성해줘.

- 내가 스크랩한 밈
- 최근 본 밈
- 관심 트렌드
- 내 스크랩 폴더

스크랩한 콘텐츠를 다시 클릭하면 해당 상세 페이지로 이동할 수 있어야 해.

- Black & White
- Minimal
- Clean
- Editorial
- Modern
- High readability
- Information-focused

**"깔끔한 백과사전 + 현대적인 뉴스/트렌드 플랫폼 + 세련된 검색 서비스"**

# 18. 기술적인 요구사항

프론트엔드는 현대적인 React 기반 구조를 사용하고 컴포넌트 단위로 깔끔하게 구성해줘.

가능하다면 다음과 같은 구조를 사용해줘.

- React
- TypeScript
- Tailwind CSS
- 컴포넌트 기반 UI
- 반응형 디자인
- REST API 또는 확장 가능한 데이터 fetching 구조

백엔드는 향후 실제 회원가입, 로그인, 스크랩, 검색 데이터 저장이 가능하도록 확장성을 고려해줘.

데이터베이스를 연결할 수 있도록 설계하고, 초기에는 mock data를 사용할 수 있게 해줘.

> **참고:** 실제 구현에서는 TypeScript 대신 순수 JSX + oxlint를 의도적으로 채택함 (CLAUDE.md 참고).

# 19. UX 원칙

사용자는 대부분 사이트에 들어온 뒤

**"이게 뭔데?"**

라는 궁금증을 해결하려고 검색할 거야.

따라서 첫 화면에서 사용자가 해야 할 행동이 명확해야 해.

불필요한 메뉴나 정보를 첫 화면에 너무 많이 노출하지 말고,

**검색 → 이해 → 관련 정보 탐색 → 스크랩**

이라는 흐름이 자연스럽게 이어지도록 설계해줘.

특히 상세 페이지는 정보를 많이 담되 복잡하게 느껴지지 않도록 섹션과 카드로 명확하게 구분해줘.

# 22. 최종 결과물

실제로 동작하는 웹사이트 프로토타입을 만들어줘.

최소한 다음 화면들이 실제로 연결되어 있어야 해.

1. 홈
2. 검색 결과
3. 밈 상세 페이지
4. 트렌드
5. 밈 사전
6. 로그인/회원가입
7. 마이페이지
8. 스크랩 목록

각 화면 간 navigation이 실제로 작동하게 해줘.

전체 디자인은 일관된 디자인 시스템을 사용하고, 단순한 기능 구현보다 **완성도 높은 실제 서비스처럼 보이는 UI/UX**를 우선해줘.

특히 홈 화면에서는 사이트의 정체성이 한눈에 드러나야 하고, **검색창이 화면의 가장 중요한 시각적 요소**가 되도록 해줘.
